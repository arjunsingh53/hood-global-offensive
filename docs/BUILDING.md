# Building and running

## Requirements

| Requirement | Version | Notes |
| --- | --- | --- |
| .NET SDK | 8.0 or newer | The project targets `net10.0`; developed against 10.0.402 |
| GPU + display | — | Only for playing; `--headless` needs neither |

The sole NuGet dependency is [`Raylib-cs`](https://github.com/ChrisDill/Raylib-cs) 8.1.0, which
carries the native raylib binaries for Windows, Linux and macOS. There is nothing else to install.

Runtime art assets: `assets/maps/low-poly-industrial-zone.glb` (the supplied map),
`assets/characters/hgo-lowpoly-tactical-operator.glb` (the world/bot character), and the weapon
view-model meshes under `assets/weapons/`. Development builds copy `assets/**` next to the
executable.

---

## Everyday commands

```bash
dotnet build                 # compile (must stay at 0 warnings, 0 errors)
dotnet run                   # play
dotnet run -- --help         # list every option
dotnet run -- --maps         # list the map catalog
```

On Windows, `play.cmd` wraps `dotnet run` and handles per-user SDK installs (see `DOTNET_ROOT`
below).

## Verify a change

The simulation runs headless, and both of these commands are CI gates
([`.github/workflows/verify.yml`](../.github/workflows/verify.yml)). They must end in
`RESULT: PASS`:

```bash
# 300-second match, 9 bots, must stay clean for the full run
dotnet run -- --headless --seconds 300 --bots 9 --skill Normal --seed 20260114

# denser, harder, shorter: 15 bots on the Hard tier
dotnet run -- --headless --seconds 60 --bots 15 --skill Hard --seed 7331
```

The report's invariant block is the contract:

```
ticks with player embedded in geometry : 0
frames with non-finite transforms      : 0
frames with over-extended grapple rope : 0
kills recorded == deaths recorded      : yes
spawns are clear of geometry           : yes
upgrade stations exist                 : yes
```

Any map change should also be spot-checked directly — `--map` works everywhere:

```bash
dotnet run -- --headless --seconds 30 --bots 9 --seed 7331 --map Playground
```

Add `--verbose` for per-tick grapple/upgrade detail and embed diagnostics. Rendering changes can
be captured from any staged screen without launching the game:

```bash
dotnet run -- --screenshot shot.png --seconds 4 --screen play
dotnet run -- --screenshot cabinet.png --screen upgrade --map Arena
```

Screens: `play`, `scoreboard`, `upgrade`, `menu`, `crosshair`, `trauma`, `impact`. `--weapon`,
`--zoom`, `--width` and `--height` shape the frame. Captures need a real GPU.

## Asset provenance

### Industrial Zone map attribution

`assets/maps/low-poly-industrial-zone.glb` is the project-owner-supplied Low Poly Industrial Zone
by novikto, licensed CC-BY 4.0. It is copied byte-for-byte from the supplied source. Keep the
bundled [attribution and provenance record](../assets/maps/LOW-POLY-INDUSTRIAL-ZONE-ATTRIBUTION.md)
with any distributed build; see the
[collision/render integration note](LOW-POLY-INDUSTRIAL-ZONE-INTEGRATION.md) for the deterministic
sidecar design.

### Runtime character

`assets/characters/hgo-lowpoly-tactical-operator.glb` is the active bot/world character, original
project art. See the [runtime asset record](../assets/characters/HGO-LOWPOLY-TACTICAL-OPERATOR.md)
and its repeatable [build script](../tools/build_lowpoly_tactical_operator.py).

### Weapon meshes and generated assets

The weapon view models under `assets/weapons/` are generated by the checked-in scripts in
`tools/` (for example [build_weapon_asset.py](../tools/build_weapon_asset.py) and
[build_ak47_viewmodel.py](../tools/build_ak47_viewmodel.py)): the repository holds the
runtime-safe result and the script holds the recipe. Meshes are only used when they load; a
missing mesh falls back to the box weapon instead of failing.

### Optional sky panorama (not bundled)

The game always includes its own procedural dusk sky. A 2:1 equirectangular PNG may optionally be
placed at `assets/sky/hgo-sunset-panorama.png`; it is validated and camera-projected at runtime.
No third-party skybox is bundled, downloaded, or redistributed by this repository. See
[the sky input contract](../assets/sky/README.md).

## Packaging a local build

To produce a self-contained build that runs without a .NET installation:

```bash
dotnet publish -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeAllContentForSelfExtract=true -p:EnableCompressionInSingleFile=true \
  -p:DebugType=None -p:DebugSymbols=false -o release/win-x64
```

Swap `win-x64` for `linux-x64` or `osx-arm64` as needed. The package lands in `release/win-x64/` as
one self-contained executable; it needs no separate .NET install or adjacent `assets/` folder.
`EnableCompressionInSingleFile` keeps the Windows package below GitHub's usual file limit.

> **Note:** the development `bin/Debug` executable is framework-dependent; use `dotnet run` for
> normal local development.

### A note on `DOTNET_ROOT`

If the SDK is installed per-user (for example in `%USERPROFILE%\.dotnet`), running the
**development** `.exe` directly requires `DOTNET_ROOT` to point at it:

```bash
export DOTNET_ROOT="$HOME/.dotnet"    # Git Bash / Linux / macOS
set DOTNET_ROOT=%USERPROFILE%\.dotnet # Windows cmd
```

`dotnet run` handles this for you, and so does `play.cmd` on Windows.

## Code style

The codebase follows the standard .NET conventions:

- File-scoped namespaces.
- Nullable reference types enabled; implicit usings enabled.
- One type per file, named after the file.
- XML doc comments on public types and non-obvious members, explaining *why* rather than restating
  the signature.
- Gameplay constants live in `Cfg.cs` or in a definition table (`WeaponDef`, `BotProfile`), never
  inline at the point of use.

The build is clean: **0 warnings, 0 errors**.
